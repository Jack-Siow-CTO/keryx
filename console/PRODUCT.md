# Keryx Console

Register: **product**

## Product Purpose

Principal operator surface for a private AI control plane. Connect over Tailnet to a Worker that remains system of record. Product metaphor is a **messaging client for agents**: home is a chat list of **Sessions** (threads with a single agent identity), plus thin system rows for cross-Session attention (**Needs you** / Inbox projection).

## Users

- Principal operator (solo or very small team)
- Desk or laptop first; phone for Approvals while mobile
- High trust, low marketing: they already understand Runs, tools, and Approvals—chrome should feel like a serious messenger, not a goal cockpit or IDE

## Tone

Calm authority. Chat-thread centric, dense enough for operators, never IDE cosplay. Messenger interaction principles (list → thread → Send), original Keryx visual system—not WhatsApp/Telegram/Slack skin.

## Anti-references

- Dual-rail operator cockpit as the default home
- Neon "AI" dashboards
- Left accent stripes on list rows
- Marketing onboarding copy
- Flat bubble spam of every tool event
- Multi-agent contact list without domain support

## Strategic principles

1. Worker is SoR; Console is thin (control-plane Principal client, not a Gateway).
2. Session = chat thread; Send when idle starts a root Run; never a silent second Active root Run.
3. Needs-you accent only for true attention (Approvals, badges); dual surface: list system row + sticky in-thread card.
4. Prose is first-class chat; tools/Child Runs/status are collapsible activity in the same timeline.
5. Global config (Memory, Skills, Schedules, Settings) in profile hub; Policy/Workspace in Session info.
6. System fonts; restrained cool-slate palette.
